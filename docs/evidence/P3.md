## 5. Defects found by the verification and fixed

1. **Cancellation never reached the stream.** The cancel registry lived on the
   `AiService` instance, and every request builds a new service, so
   `POST /ai/executions/{id}/cancel` set a flag nobody was watching. Moved to a
   process-wide registry created once in the lifespan.
2. **`/ai/executions` returned 500.** `AiExecutionOut` lacked
   `from_attributes`, so ORM rows could not be validated.
3. **Queue jobs dead-lettered** with *"Event is bound to a different event loop"*.
   The governor stored an `asyncio.Condition` created on the API loop and awaited
   it from the worker thread's loop; the gateway cached an `httpx.AsyncClient`
   the same way. Fix: polling admission and one client per loop — verified by a
   real enqueue → worker → result run.
4. **Pull endpoints were unreachable.** `/ai/models/{tag:path}` matched
   `pulls/{id}`; moved to `/ai/pulls`.
5. **`nomic-embed-text` looked uninstalled** while Ollama reports
   `nomic-embed-text:latest`. Added tag normalisation and a test.
6. **Benchmarks could be "superseded" by a reference row** written in the same
   second. Added explicit `source` provenance with a migration and backfill.
7. **Validation errors reached the UI as `[object Object]`.** Added a
   `RequestValidationError` handler returning the standard envelope and a client
   that renders it.
8. **Execution history intermittently came back in the wrong order.** ULIDs were
   time-ordered only to the millisecond and random within it, so two rows written
   in the same millisecond sorted arbitrarily. `new_ulid()` now increments the
   random component inside a millisecond (strictly increasing), and a 2 000-id
   test pins it. The flake reproduced 1-in-3 full-suite runs before the fix and
   has not reappeared in 3 consecutive runs after it.

## 8. Known limitations (stated, not hidden)

- **Non-streamed generations cannot be cancelled mid-flight.** Ollama has no
  cancel endpoint; cancellation works between stream chunks only.
- **Concurrency is 1 by default** and throughput is bounded by it: ~45 tok/s means
  a 200-token caption takes ~4.5 s, and a batch of 20 runs sequentially.
- **`qwen3:4b` runs partially on CPU** (69 % placement, 15.5 tok/s). Planning only.
- **TTFT is reported only for streamed runs**; non-streamed Ollama responses do
  not expose a first-token timestamp, so the benchmark shows `-` rather than an
  estimate.
- **No GGUF import from a local file**; only Ollama-library tags can be pulled.
- **Vision models are installed but no vision task uses them yet** (Phase 5).
- **`/ai/chat` is implemented and tested but not exposed in the UI** — the
  Playground uses `/ai/stream` with a system prompt, which covers the same ground.
