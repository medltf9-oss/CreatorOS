### Analytics consent (P8.20)

The permission upgrade is implemented once, in the existing engine and vault, and is exercised against
recorded provider payloads (category A). `services/social/consent.py` computes the exact difference
between what analytics needs on this account's login path and what it holds, and reports the non-OAuth
blockers separately. `OAuthEngine` gained an account-bound upgrade: the provider identity is verified
before anything is written, the new credential is stored before the old one is revoked, a denial or a
vault failure leaves the account connected, and capabilities are re-evaluated from the verified facts
(never from the fact that OAuth succeeded).

| Test group | What it pins |
| --- | --- |
| planning | Facebook/Instagram-Login/Instagram-Facebook-Login/TikTok request exactly the missing insight scope and never a publishing scope; a Page task, a development-mode app and an unsupported account are each reported as themselves; already-granted is a no-op |
| upgrade | the same account row is kept, existing scopes are preserved, the old credential is revoked only after the new one is stored, capabilities become `available` only when the provider granted the scope, a partial grant stays `needs_user_consent` |
| safety | user denial and provider denial preserve the account and its credential (audited as `analytics.consent.denied`); an identity mismatch refuses without touching the account; a vault failure during adoption preserves the old credential; the callback is single-use; two concurrent upgrades are distinct transactions |
| API | the routes require the session token; an unknown account is `404`; a client-supplied scope list is `422` |

### A fix found while wiring the API

`_seed_workforce()` flushed the metric registry, the Phase 8 grants and the analytics prompt seeds but
never committed, and the `with session_factory() as session:` block only closes a session. Those
seeds were therefore rolled back on every boot, which is why the API saw an empty catalogue. A
trailing `session.commit()` now persists them. (The pre-existing agent/tool seeds committed earlier in
the same function, which is why the workforce always looked correct.)
